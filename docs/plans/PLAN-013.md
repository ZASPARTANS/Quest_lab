## Facts checked today (official GitHub pages; `docs/SOURCES.md` after step 13.0)
- Published Pages sites "may be no larger than 1 GB"; deployments time out after 10 minutes; soft limits 100 GB/month bandwidth. Our site: about 265 MB (forecast data 64 MB, stored base map 190 MB, fonts and sprites 12 MB, the page about 2 MB).
- Custom workflow publishing: `actions/configure-pages`, `actions/upload-pages-artifact` (artifact under 10 GB), `actions/deploy-pages`; the deploy job needs `pages: write` and `id-token: write` and an `environment: github-pages`.
- Standard runners are free for **public** repositories (so the 6-hourly job costs nothing; D37 holds).
- **NOT verified, to be tested on the real site (step 13.5): that Pages answers HTTP range requests for the 190 MB file; which response headers it sends (I expect no custom headers, so the security policy goes into a `<meta>` tag); that a 265 MB artifact deploys inside the 10-minute limit; that a private repo would work (not needed).**

## Assumptions
- **A36:** the site is served from a sub-folder (`/Quest_lab/`), so every address the page builds must start from the page's own base. Vite's `base` setting handles the bundle; the page's own data addresses (`data_url_path` `/data/`) are made base-relative in one place (`app.js`, from `import.meta.env.BASE_URL`); the local preview and the tests keep working at `/`.
- **A37:** the 190 MB base-map file stays out of git (A27) and travels as a **GitHub Release asset** (`basemap-v1`) with its sha256 in `config/`, downloaded and checked by the build; fonts and sprites are fetched by the existing hash-locked `basemap fetch-assets`.
- **A38:** ECMWF's files for the 00z and 12z runs appear about 7.5 h after the run (DOMAIN, step 3 notes); the fetch step already picks the newest complete run, so the schedule only decides freshness: cron at 02:20, 08:20, 14:20 and 20:20 UTC.
- **A39:** if a build fails, the previous site stays up and the page's own age warning grows (the public status file is written only by a successful build): a failed refresh is visible to visitors through the age line, and to the owner in the Actions log.
